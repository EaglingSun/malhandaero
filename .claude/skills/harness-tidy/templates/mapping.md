- 원본: `{경로}.bak` ({N}줄) · 정리본: `{경로}` · 판: harness-tidy {VERSION} · 날짜: {날짜}

- 변경 유형: 유지 · 수정 · 묶음 · 이동 · 뺄 다섯 가지만 쓴다 (뺄 · 이동 · 묶음 행도 지우지 않는다)
- 새 ID 칸: 규칙(행동을 지시 · 금지하는 문장)이면 ID — Rules 절 밖 · procedure.md · pitfalls.md 로 옮긴 규칙도 같다. ID 를 두지 않으면 `없음(사유: …)` — 빈칸 · `—` 금지 (HT-07)
- 원본에 ID 가 있던 규칙을 빼면 새 ID 칸에 그 ID 를 적고, 그 번호는 다시 쓰지 않는다
- 원본 줄은 Grep 도구 출력 기준 (HT-03)
- Eval 케이스 칸: evals.json 의 id (여러 개는 쉼표). 케이스를 두지 않으면 `없음(사유: …)` — 빈칸 금지
- 묶음 행은 원본 문장마다 케이스를 둔다 (묶다가 한쪽 뜻이 빠지는 것을 잡기 위해)
- 확인: `python scripts/inventory.py --coverage evals/{대상}` — 커버리지 100% · ID 없음 0 · 변경 유형 오류 0 이어야 exit 0
