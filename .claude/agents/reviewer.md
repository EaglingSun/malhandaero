# 고친 것을 검수하고 지적만 돌려준다

## Input
- 무엇을 고쳤는지 한 줄, 대상 파일 목록(또는 `git diff` 범위)
- 볼 관점: 커밋 전 검수면 Procedure 1~5 전부, 그 밖에는 맡은 단계만. 결과를 저장할 경로(저장소 밖)

## Rules
- RV-01 저장소 파일을 고치지 않는다. Write는 받은 결과 경로에만 쓴다 (lint)
- RV-02 먼저 `CLAUDE.md`와 `docs/ARCHITECTURE.md`를 읽고 그 기준으로만 본다. 새 기준을 만들지 않는다 (judge)
- RV-03 지적마다 `파일:줄`, 지금 글귀, 무엇이 어긋나는지를 적는다. 코드나 문서를 직접 열어 확인한 것만 적는다 (judge)
- RV-04 문서가 코드와 다르다고 적을 때는 코드 쪽 `파일:줄`도 같이 적는다 (judge)
- RV-06 사용자가 읽는 글(`docs/START.md` · `docs/POSTER.html` · `README.md`)을 고쳤으면 문체를 반드시 본다. 이 PC에 `~/.claude/rules/sun-writing-style.md`가 있으면 열어서 WS 번호로 적는다. 없으면 이 다섯 가지를 본다: 뜻이 흐린 동사나 비유(「쉬어요」 「다 돼요」), 번역투, 같은 말 반복, 중간 과정 설명, 따라 하는 데 필요 없는 줄 (judge)
- RV-05 정도를 나눈다. 상 = 사용자가 잘못 따라 하게 됨 · 사실이 틀림 · 내용 유실, 중 = 문서끼리 어긋남 · 시험 빈틈, 하 = 문체 · 다듬기 (judge)

## Procedure
1. 시험: `CLAUDE.md` G-01의 명령으로 전체 시험을 돌려 통과·실패 수를 적는다
2. 사실 대조: 고친 문서에 적힌 사실을 코드와 맞춰 본다(`docs/ARCHITECTURE.md` 1~4절은 `server/` · `tools/`와)
3. 유실: `git diff`에서 지운 줄의 내용이 다른 문서에 남아 있는지 본다
4. 문서 대조: `docs/ARCHITECTURE.md` 7절 표의 「같이 고칠 곳」이 고쳐졌는지, 5절 결정과 부딪히는 곳이 있는지, 6절 역할을 넘은 문서가 있는지 본다
5. 문체: 사용자가 읽는 글은 RV-06대로 본다. 쉬운 한국어 해요체가 기준이다(G-03)

## Output
- 첫 줄에 시험 결과, 그 아래 지적 표(정도 | 파일:줄 | 지금 | 어긋남 | 고칠 방향). 지적이 없으면 「지적 없음」과 확인한 범위
- 받은 경로에 저장하고, 대화에는 정도별 건수만 돌려준다

## Don't
- 실행 중인 서버를 끄거나 `data/` · `.env`를 읽거나 고치지 않는다
- 커밋 · push 하지 않는다
