### 세션 요약
CLAUDE.md·docs/HANDOFF.md를 .gitignore로 빼려다 클라우드 세션 개발이 끊긴다는 이유로 커밋 전에 원복했다. harness-tidy v1.1.0을 `.claude/skills/`에 파일째 넣어 커밋·push(30e6d46).

### Lessons Learned
**시행착오**
- 중첩 git clone을 그대로 두면 `git add`가 gitlink만 올려 클라우드에서 빈 폴더가 된다 → 중첩 `.git`을 빼고 파일째 커밋. `rm -rf`는 hook이 막아 scratchpad로 `mv`.
- push 거부(origin에 다른 세션 커밋 8개) → 작업 트리가 깨끗한 것을 확인하고 `git pull --rebase origin main` 후 push.
- `.venv`에 pytest가 없었다 → `requirements-dev.txt` 설치.

**발견한 패턴**
- 자동 업데이트는 `git status --porcelain --untracked-files=no`(server/updater.py:92)라 untracked 폴더(.claude/ 등)는 업데이트를 막지 않는다.
- 저장소에서 파일을 빼면(`git rm --cached`) 내 PC는 남지만 다른 사람 PC·클라우드 세션은 다음 pull에서 그 파일이 사라진다.
- 앱의 `claude -p`는 임시 폴더를 cwd로 쓴다(server/llm.py:277) → 저장소 `.claude/skills`는 앱 추출에 쓰이지 않는다. 앱 회의록은 `server/extract.py` 지시문이 정본.
- pytest는 `.`으로 시작하는 폴더를 수집하지 않아 `.claude/skills/*/tests`가 앱 시험에 섞이지 않는다.

**의사결정과 근거**
- Claude 개발 파일은 저장소에 둔다(실장): 클라우드 세션에서도 이어서 개발하기 위해.
- harness-tidy는 프로젝트 스코프에 파일째 커밋(실장 승인): 클라우드 세션에서도 쓰기 위해. 모든 사용자 PC에 폴더가 깔리지만 앱 동작에는 영향 없음.

**사용자 정정**
- ignore 방안(B)을 승인했다가 「클라우드 세션에서 개발 못 한다」로 취소. 제안 단계에서 클라우드 세션 영향을 짚지 못했다.
