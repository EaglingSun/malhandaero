# 회의록 형식 (말한대로 표준)

말한대로가 회의·통화 녹음에서 만드는 회의록과 할 일의 형식. 앱의 추출 지시문(`server/extract.py`), 내보내기(`minutes_markdown`),
그리고 Claude Code 스킬 `skills/meeting-minutes`가 모두 이 문서를 기준으로 한다. **형식을 바꿀 때는 이 문서를 먼저 고치고 셋을 맞춘다.**

## 1. 원칙

| 원칙 | 뜻 |
|---|---|
| 할 일은 적게, 회의록은 빠짐없이 | 내 할 일은 회의당 **5건 이하**로 묶는다. 묶느라 빠지는 잔일은 상위 할 일의 **세부**에, 할 일이 아닌 언급은 **회의록 요점**에 남긴다 |
| 담당자가 불리면 남의 일 | 이름·화자 표기로 담당자가 불린 일, 내가 "~해 주세요"로 시킨 일은 **맡긴 일**. "불분명"은 아무도 담당을 말하지 않은 일에만 |
| 회의록은 문서 | 다른 사람에게 그대로 보낼 수 있어야 한다. "~라고 했어요" 같은 대화 중계 대신 **내용 자체**를 적는다. 발언자는 의견이 갈릴 때만 괄호 |
| 녹음에 없는 말은 쓰지 않는다 | 추측·보충 금지. 모르면 "확인할 것"에 넣는다 |
| 쉬운 한국어 | 화면 문구와 요약은 해요체. 회의록 요점은 한 줄 30자 안팎 |

## 2. 자료 구조 (추출 결과 JSON)

```json
{
  "summary": "- 결정·중요 내용 2~4줄, '- '로 시작, 해요체",
  "items": [
    {"text": "LCT 테스트 계획을 개발팀과 확정하기", "owner": "me|other|unclear", "who": "민수",
     "due": "내일", "dueDate": "2026-11-11", "time": null, "scope": "회사", "quote": "근거 원문 한 문장",
     "details": ["요구사항 리스트 받기", "스킬 리스트 기한 정하기"]}
  ],
  "minutes": {
    "attendees": ["지은", "민수"],
    "topics": [{"topic": "GTest 지원", "points": ["요점 3~5개"], "decisions": ["정해진 것"]}],
    "questions": ["결론이 안 나 확인할 것"],
    "next": ["11/16 RT 시작", "내일 기획회의"]
  }
}
```

- `items[].owner`: `me` 내 일 → 「대신 적어 뒀어요」 / `other` 맡긴 일 → 「들은 이야기 ▸ 맡긴 일」 / `unclear` → 내 목록에 "누구 일인지 확인" 표시
- `items[].details`: 상위 할 일 아래 묶인 세부. 각 20자 안팎, 12개까지
- `minutes.topics`: 회의 순서대로. 주제당 `points` 3~5개(비슷한 말은 합침), `decisions`는 그 주제에서 정해진 것
- DB: `inputs.summary`, `inputs.minutes`(JSON), `items.details`(JSON)

## 3. 내보내기 (Markdown) 틀

`GET /api/inputs/{id}/minutes.md`, 화면의 「회의록 복사 / 파일로 받기」가 내는 꼴.

```markdown
# {제목}

일시: {YYYY-MM-DD}
참석: {attendees, 쉼표}

안건: 1. {topic} · 2. {topic} · …

## 요약
- {summary 줄}

## 1. {topic}
- {point}
- **결정** {decision}

## 결정 사항
- {모든 topics의 decisions 모음}

## 확인할 것
- {questions}

## 할 일
- [ ] {내 일} (나 · {기한})
    - {세부}
- [ ] {맡긴 일} ({담당} · {기한})

## 다음 일정
- {next}
```

비어 있는 구획(참석·안건·확인할 것·다음 일정 등)은 통째로 생략한다. 내 일에서 "안 함"으로 넘긴 항목은 빼고, 맡긴 일은 모두 넣는다.

## 4. 추출 지시문의 핵심 규칙 (요약)

1. 묶어서 뽑기: 같은 주제·같은 담당자의 잔일 → 상위 할 일 1개 + `details`. 내 일 ≤5개
2. 담당자 판정: 이름이 붙으면 `other`, 내가 시킨 일도 `other`, 아무도 담당을 말하지 않은 일만 `unclear`
3. 할 일로 안 뽑은 작은 언급은 `points`나 `questions`에 남긴다
4. 회의록 요점은 한 줄 30자 안팎, 대화 중계 금지, 발언자는 의견이 갈릴 때만 괄호
5. 기한: 원문 표현(`due`) + 날짜(`dueDate`, 오늘 기준 가장 가까운 앞날), 시각은 나왔을 때만
6. 긴 글(지시문 1만 자 초과)은 더 센 모델(opus)로, 조각은 6만 자 단위(1~2시간 회의는 한 번에)

## 5. 예 (실제 회의록 37k자 → 결과 모양)

- 요약 4줄 · 주제 9개(주제당 4~8요점, 결정 0~4) · 확인할 것 8 · 내 일 2 · 맡긴 일 7(민수)
- 내 일 예: "CT 기획회의에서 개발팀과 RT 테스트 범위와 역할 분담 합의하기 (내일)" + 세부 7개
- 맡긴 일 예: "GTest로 만든 테스트를 CT로 가져와 실행·측정하는 검증 시나리오 만들기 (민수 · 오늘)" + 세부 6개
